# Public update history

Add one short entry per meaningful visitor-facing improvement to src/content/site-release-notes.json in the same release as the change. Use a unique stable id, actual publication date, plain-language title and detail, and a relevant local link. Multiple entries may share a date. Keep older entries.

The build automatically validates and publishes the entire list. It derives the unread badge from the content, so rebuilding unchanged code does not pretend a new improvement shipped. Technical maintenance without a user-visible change does not need an announcement. Do not expose private notes or raw commit messages. Verify publication before describing an entry as live.
